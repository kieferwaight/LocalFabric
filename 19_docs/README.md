# 19_docs/

Auto-generated by `make docs-all`. **Do not edit by hand** — changes
will be overwritten on the next regeneration.

## Layout

One Markdown file per definition `id`, mirroring the source-bucket
layout on disk:

```
19_docs/
├── 01_schemas/              # *.schema.yaml definitions
├── 02_core/                 # stdlib primitives + abstract bases
├── 06_workflows/            # composed pipelines
├── 07_tasks/                # atomic task YAML wrappers
├── 09_docker/               # docker service definitions
├── 09_launchd/              # macOS launchd job definitions
├── 12_prompts/              # markdown prompts (compiled to YAML)
├── 13_models/               # model registry entries
├── 13_providers/            # provider registry entries
├── 14_templates/            # rendering templates
├── 15_examples/             # example/demo definitions
├── index.md                 # catalog-wide API reference index
└── schema.md                # YAML authoring schema reference
```

Each `<id>.definition.md` file is rendered from the
`docs.definition.template.definition` template against the catalog
entry for that id. The two catalog-wide pages (`index.md`, `schema.md`)
use `docs.catalog.template.index` and `docs.catalog.template.schema`.

## Regenerating

```bash
make docs-all       # regenerate every page
make docs-check     # verify everything is up to date (exits non-zero if stale)
```

The generator lives at
[`02_core/runtimes/yaml/regenerate_docs.py`](../02_core/runtimes/yaml/regenerate_docs.py).
It walks every YAML and markdown definition across the listed buckets,
builds a single Runtime catalog, and renders one page per entry.
